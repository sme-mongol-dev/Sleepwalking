## Reproducible checks

Run in a free checkout with no other Unity Editor instance holding this project:

```powershell
& 'C:\Program Files\Unity\Hub\Editor\6000.3.28f1\Editor\Unity.exe' -batchmode -nographics -quit -projectPath 'T:\Sleepwalking' -executeMethod Sleepwalking.Audio.Editor.SleepwalkingAudioBuilder.Validate -logFile "$env:TEMP\sleepwalking-audio-validation.log"
```

The first `Rebuild` Unity batch run returned exit code 0 and logged `Sleepwalking audio: catalog, prefab, four ambiences, and cue variants validated.` It imported 26 clips and wrote the catalog and prefab in this directory. `Validate` checks the prefab/catalog binding, Resources load path, four nonempty ambience clips, the nonempty menu music clip, and all cue variants. The Director routes room music and dream ambience through separate AudioSources. `EnterDream` stops and clears the music clip; `EnterRoom` stops and clears dream ambience. `StopAll` clears both. These routing rules have been reviewed in code; an audible Play Mode session or Windows build listening pass has not been performed here.

The independent Sound lead checked all five OpenGameArt source pages for explicit CC0 licensing, verified the 26 audio file headers, matched the 22 `sfx100v2_*` files byte for byte against the downloaded CC0 ZIP, and checked all 33 serialized GUID references (28 unique) against `.meta` files. The lead identified issues in the prefab loader, initial state, stopping, per-cue volume restoration, and validation; those were fixed before final handoff. The first Unity `Rebuild` passed before the final prefab loader and validation changes; a second compile/import is pending in the shared checkout.

The final runtime and editor C# sources were also compiled locally against Unity 6000.3.28f1's managed assemblies with `dotnet build`: 0 errors, 1 expected CS0649 warning because the standalone compiler cannot see Unity's serialized assignment to `catalog`. This checks syntax and API references; it does not run Unity's asset pipeline.
