# Visual module integration

Owned assets: `Assets/SleepwalkingVisual/`. The shared assembly scene is owned by Game Mechanics.

## Room

- Prefab: `Assets/SleepwalkingVisual/Prefabs/SleepwalkingRoom.prefab`. Instantiate once at the scene origin, without scaling. It contains editable mesh objects and a camera.
- `Sleepwalking.Visual.RoomHotspot` marks the four menu targets. Each has a non-trigger `Collider`, `Action` (`Dream`, `Settings`, `Credits`, `Quit`) and an English `Label`. The bed and hero both report `Dream`. UI should call `RoomHotspot.Raycast(roomCamera, Input.mousePosition)`; this maps window coordinates to the camera's low-resolution render texture.
- `Sleepwalking.Visual.RoomEnvironment` on the prefab root exposes `SetWakeCount(int)` for small changes to the clock hand, picture, loose book, curtain and window star after each completed dream. Count zero restores the initial state; dream hotspot labels switch from `New Game` to `Next Dream` after the first completed dream. Game Mechanics owns when to call it.
- `Sleepwalking.Visual.PixelRoomView` on the camera renders the live 3D scene at a low resolution (default 320×180) and displays it using a point-filtered `RawImage` behind UGUI. It can also be attached to the gameplay camera to pixelate the live levels: choose `BaseWidth` and `BaseHeight` and keep gameplay UI at a higher Canvas sorting order. Hide the existing UI's opaque menu backdrop when the room is visible. The component follows the current screen aspect ratio while keeping at least the configured pixel dimensions.
- The included `Assets/SleepwalkingVisual/Preview/RoomPreview.unity` is isolated for visual inspection and is not added to build settings.
- Optional second room: `Assets/SleepwalkingVisual/Prefabs/SleepwalkingRoom_IllustratedHero.prefab`. It inherits the editable base room, keeps all five menu colliders and replaces only the hero renderers with a separate textured 3D quad. `BuildIllustratedPreviewPlayer()` copies the current shared scene into `Preview/IllustratedMenuPreview.unity`, changes only `SleepwalkingGame.RoomPrefab` there, and builds `Builds/VisualPreview/SleepwalkingIllustrated.exe`. The base `SleepwalkingRoom.prefab` remains the default in `Builds/Windows/Sleepwalking.exe`. The two current scene YAML files have the same 232 lines and differ only at the `RoomPrefab` reference.
- Isolated preview for the optional room: `Assets/SleepwalkingVisual/Preview/RoomPreviewIllustrated.unity`. It contains one instance of the full variant prefab, including its own inherited `PixelRoomView` camera. Play it at 1024×768 to obtain a 320×240 point-filtered RenderTexture without changing the shared scene.
- The alternate hero source is in `Textures/Source/SleepingHero_Generated.png`; Tessera's 96×64 output and its exact UI-palette version are in `Textures/Processed/`. The cutout uses point filtering, no mipmaps and an alpha-cutout URP shader.

The window is grouped under `Moon Window` and offset left by 0.9 world units, leaving the Quit door visually distinct at the right of the room. Both room variants inherit this composition. The base room remains the integrated default; the illustrated room remains a separate choice.

## Dream themes

- `Assets/SleepwalkingVisual/Prefabs/Themes/` contains four style prefabs: Meat, PostApocalypse, DeepWater and Heaven. Each has a separate generated pixel backdrop, its own original TL tileset material, and a temporary neutral Dreamer silhouette. The old flat prefabs are preserved in `Prefabs/Themes/Flat/`; `MeatTexturePilot.prefab` remains a separate rejected experiment.
- `Textures/Tilesets/TL_{Meat,PostApoc,DeepWater,Heaven}_Dream.png` are byte-identical copies of the supplied production tilesets in `Docs/UI/References/`. They are imported as 3×6 cells of 32×32 pixels, with point filtering and no texture compression. `DreamTheme.ApplyTo(geometryRoot)` adds no-collider tile meshes under level objects marked `SleepwalkingTileSurface` while retaining the authored BoxCollider2D, route, traps and readability cues. It also applies the theme's materials to the existing geometry renderers.
- `DreamPlayerAppearance` replaces the gameplay square's visible renderer with a no-collider child sprite after the `Dreamer` appears. This is a replaceable silhouette, not an approved final character design. The gameplay actor and its collider remain owned by Game Mechanics.
- Current tiles render with the PNGs' original colours because the owner most recently identified them as the actual working tilesets. An earlier instruction restricted the palette more broadly; this implementation does **not** establish that the global palette restriction has been permanently removed. Keep the unmodified originals so a palette remap can be selected later without recutting the atlas.
- The level owner chooses the theme on each visit. The main game scene loads these four theme prefabs; `Preview/TileShowcase.unity` is an isolated material/geometry check, not a gameplay level. Its Player accepts `-tileLevel=1..7` and `-tileStyle=0..3` (Meat, PostApocalypse, DeepWater, Heaven).
- `BuildDreamLevelPreviewPlayer()` copies the current shared scene to `Preview/DreamLevelPlayerPreview.unity` and adds a QA-only auto-start component. Its Windows Player accepts `-previewLevel=1..7`; `-previewView=X,Y` freezes and places the Dreamer to inspect a specific camera view without claiming a traversal. `CaptureIllustratedMenu.ps1` accepts `-WaitMs` for mechanism frames. These preview controls do not exist in the main or illustrated release candidates.
- The calibrated L06 prefab has a collider-free white/cyan right-pointing chevron in `Readability` at the Start edge. It remains in the camera when the horizontal mover leaves the frame; the moving platform and its tile children travel together. Current shared-scene default movement profile is `02_Responsive.asset`. The main and illustrated Players were rebuilt from the same scene/runtime after this cue; their serialized scenes differ only at `RoomPrefab`.

## Regeneration and preview

Run `Sleepwalking/Build Visual Assets` in the Unity Editor to regenerate materials, the room prefab, four theme prefabs and `Assets/SleepwalkingVisual/Preview/RoomPreview.unity`. The preview scene is isolated and remains outside build settings; generation checks its prefab instance and scene roots before saving. The room composition follows the saved reference frames: wall shelf on the upper left, clock and calendar near the centre, curtained moon window on the right, nightstand behind a wide bed. The required quit door sits at the far right edge. Every furniture, prop and shell piece remains a separate Unity object.

This document records the module API. Integration and end-to-end testing belong to the shared assembly scene.
