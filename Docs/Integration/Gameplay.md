# Game Mechanics integration contract

Owner: `Assets/SleepwalkingGameplay/` and `Assets/Scenes/Sleepwalking.unity`. The scene contains `SleepwalkingGame` and is the Windows build entry point.

## Game loop

`SleepwalkingGame` begins in the room and subscribes to `SleepwalkingUI.DreamRequested`, `RestartRequested`, and `MainMenuRequested`. `StartDream()` plays a short sleep transition and instantiates the next level. The first two dreams are Tutorial1 and Tutorial2, each followed by a wake transition to the room. `tutorialStage` advances separately; `completedDreams` counts only main levels. After Tutorial2, main level index is `completedDreams % DreamCount` and cycle is `completedDreams / DreamCount`; the current scene has eight main levels, L01–L08. They repeat without tutorials. Styles on the first main cycle come from `SleepwalkingLevelDefinition.FirstCycleStyle`; later styles are randomized independently. `roomChange` advances after every tutorial and main dream, so the room changes after each wake. Returning to the main menu resets the session and tutorials. Progress is session-only.

## Level assets

The scene builder loads `Assets/SleepwalkingLevels/Prefabs/Tutorial01_DreamGeometry.prefab` and `Tutorial02_DreamGeometry.prefab` into `TutorialPrefabs`, then assigns L01 through L08 in `LevelPrefabs`. It uses the marker and feature contract in [Levels.md](Levels.md). If a main prefab is temporarily unavailable, runtime fallback geometry makes the scene playable. Prefabs are not modified at runtime; only instances and their mechanism state are changed. `SleepwalkingLevelFeature.Kind` values drive spikes, saws, laser bases/beams, timed platforms, moving platforms, and buttons. A button's `LinkedFeatureId` temporarily disables matching hazards; for lasers it disables the beam while the visible, lethal emitter remains active.

All gameplay is 2D XY. The player uses only `Rigidbody2D`, with a collision width of 0.55 and height of 1.0. Solid objects use shaped 2D colliders; lethal surfaces use 2D trigger colliders. The prefab's 0.04-unit laser beam is expanded on its runtime instance, including its mesh and 2D trigger, to `3.5 × (2 × camera orthographicSize) / logical pixel height` world units. The logical height comes from the room camera's 320×180 baseline adjusted for aspect ratio; it preserves the authored beam width while dreams render directly to the screen. The runtime width follows the current vertical camera size and aspect ratio. The authored prefab remains untouched and receives the same runtime width on every cycle.

`TimedPlatform` uses its authored `ActiveSeconds` as the solid part of `CycleSeconds`; the value is clamped into the cycle, and `PhaseSeconds` offsets the timed state after a retry. `MovingPlatform` uses a kinematic `Rigidbody2D.MovePosition` in `FixedUpdate` and a cosine path from the authored transform to `MoveOffset` and back. A standing player receives the platform's movement velocity without losing horizontal input. The platform's zero-friction physics material prevents double horizontal carry; a side contact does not attach the rider. Reset returns the platform to the authored transform and clears the rider's inherited speed. Current authored moving features have `PhaseSeconds = 0`; moving paths intentionally start at the authored transform regardless of phase. The L05 timed state and L06 horizontal/vertical rider tests passed in `Docs/QA/mechanism-physics-rerun-results.xml`. L07 contains no authored moving platform, so that optional branch was skipped. Keyboard-controlled traversal remains unverified.

## Controls and events

Keyboard: A/D or arrows move on the ground, Space/W/Up jump or wall jump, Shift dashes, Escape pauses. Tutorial1 disables Shift dash in the controller; Tutorial2 enables it. The running cap is 5 cells per second before the Odradek multiplier. A/D changes airborne horizontal velocity with 27% of ground acceleration, so reversing direction takes time. A full dash travels at most 2.7 cells; its direction stays fixed until it ends, then airborne control continues from the pre-dash momentum. Wall jump applies a separate horizontal impulse. The controller includes coyote time and jump buffering. Every solid wall, including cave boundaries and platform sides, supports wall-jump; no special wall marker is required. A lethal collision calls `SleepwalkingGame.KillPlayer(Vector2 contact)`, leaves a session-only paint mark, plays the nine-frame death sequence, then moves the player and camera smoothly to the start over 0.6–1.4 s depending on distance. During the return the player cannot move or die again. The mark persists across retries on that level; leaving it clears all marks. Touching the bed exit calls `CompleteDream()`.

The builder assigns `Assets/SleepwalkingVisual/Prefabs/SleepwalkingRoom.prefab`, its `RoomHotspot` objects, and the four prefabs from `Assets/SleepwalkingVisual/Prefabs/Themes/`. `RoomEnvironment.SetWakeCount` applies each room change. `PixelRoomView` renders the room to its low-resolution texture, then disables that output and clears the camera target texture when a dream starts. Dream levels render directly at the screen resolution, using their original point-filtered tile textures without another pixelation pass. On waking, the room render texture and output return. In dreams the orthographic camera follows the player smoothly on X, keeps its vertical size based on playable height, and clamps to the level's left and right limits. Wide levels extend beyond one frame. The backdrop follows the camera window at its source aspect ratio. `DreamPlayerAppearance` plays idle/run/jump/climb plus the supplied 14-frame dash and nine-frame death sheets; death takes priority over dash. If the room prefab is unavailable, a simple editable room is generated. `SleepwalkingAudioDirector.CreateOrGet()` supplies menu music, dream ambience, and action cues; it requires its Resources prefab.

## Build

The editor menu `Sleepwalking/Gameplay/Build Integration Scene` regenerates only the shared scene and build scene list. `Sleepwalking/Gameplay/Build Windows` creates `Builds/Windows/Sleepwalking.exe` and a build log. Run the scene builder after prefabs become available to serialize their references.
